# Contributing

Thanks for helping build BadMelon.

## Project Direction

BadMelon is being rebuilt from requirements first. Before large implementation work, prefer updating the relevant docs so product and technical decisions stay visible.

Start with:

- [Functional requirements](docs/functional-requirements.md)
- [Non-functional requirements](docs/non-functional-requirements.md)
- [Future ideas](docs/future-ideas.md)

## Development Expectations

- Keep changes focused and easy to review.
- Add or update tests for behavior that affects pantry math, authentication, authorization, shopping lists, meal planning, or ingredient matching.
- Prefer clear, boring technology choices unless the requirements justify more complexity.
- Keep secrets, credentials, connection strings, and local environment files out of source control.
- Update documentation when behavior, setup, or architecture changes.

## Commit And Pull Request Guidelines

- Use concise commit messages that describe the user-facing or technical change.
- Include a short summary of what changed.
- Mention tests or checks that were run.
- Call out migrations, configuration changes, or follow-up work.

## Code Style

Project-specific style rules will be added after the API and frontend are scaffolded.
